## 一、背景

**项目是什么**：把《魔兽争霸3》（WC3）**真的跑到网页上**。目标是**官方对战图 Terenas Stand** 的完整客户端+服务端（每个单位/建筑/技能/图标都来自真实游戏数据），最终打包成手游（Capacitor APK）给同学玩。

**怎么做的**：
- **代码基底**：抄了 FOC web（`Fight of Characters 7.7b` 地图的网页版，作者已开源，README 可查）——**directly 搬作者的 client+server**，地图换成官方的 Terenas 对战图。
- **只保留我们自己的渲染方法**：作者用 Three.js WebGL，我们要求换成 **WebGPU 渲染**（还未完成，见遗留问题）。
- **数据全部来自真实游戏**：MPQ 原件 893MB（war3.mpq/War3x/War3Patch，来自 Win11 完整 1.27 中文版）解包 → 管线（slk.py/unittypes.py/abilities.py/mdx2gltf 等）转 JSON/GLB/PNG → 引擎按官方数值运行（伤害用 GameplayConstants、技能用 AbilityData.slk、训练/建造用 UnitBalance.slk）。

**部署现状**：`systemd-run --user --unit=war3web` 跑在 `http://192.168.31.204:8080/`（Win11 可玩；流程：填名字→加入红方→准备→进游戏）。代码在 `/mnt/shared/war3/war3web/`，仓库 `github.com/chentianxiong123/war3web`（gitignore 拦了资源 assets/mpq/war3_extracted/，可按 tools/ 管线重建）。

## 三、遗留问题声明（现在仍然有问题！）

### 1. 【用户点名】图标仍然不符合心意 ❗

用户原话：*"每一个游戏图标 角色图标或者 技能图标 功能图标 全都不是真的""图标仍然不符合我的心意"*。要求**查证真实项目看原版做没做到底**。

**查证结论（对照作者原版 foc-web）**：作者原版是**做到底的**——他的 hud.json 每个按钮都有 art 图（`/assets/ui/move.png` 等 12 个）、技能卡有 art.icon、大厅英雄卡烘焙了 26 张 PNG（tools/hero_portraits.mjs）。**我们没做到底**，具体断点：

| 图标元素 | 现状 | 断点原因 |
|---|---|---|
| 建造/训练按钮（#commands） | ✅ 真图标 9/9 | 已修（MPQ 提取 10 个） |
| hud 命令按钮（move/stop/attack/hold/patrol/skill/cancel） | ⚠️ `/assets/ui/*.png` 存在，但**未确认是否真实 CommandButtons 图**，且页面是否渲染未核对 | hud_assets.py 从 BTN 复制，需核对文件名/加载 |
| 技能按钮（#abilities） | ❌ **大面积无图**，只有 7 个人族技能有手工映射 | 根因见下 |
| 单位头像（角色图标） | ❓ 游戏内单位头像是 unitPortrait 3D 模型渲染，不是 WC3 2D 头像图 | 未查证原版/官方头像图资源 |
| 物品图标（inventory） | ❓ itemtypes 273 个全有 icon，但库存渲染链未验证 | 未接 |

**技能图标缺失的根因（已查实，不是玄学）**：
1. **字段读错**：`data/abilities.json` 里图标的真名是 **`art.icon`**（如 `Ahea.art.icon = 'ReplaceableTextures\CommandButtons\BTNHealOn.blp'`，来自 HumanAbilityFunc.txt 的 `Art=`），但客户端 `client/js/hud.js` 读的是**顶层 `a.icon`**（永远 None）→ 技能卡全无图。**管线一直都有图标数据，是消费端读错字段 + 没转 png URL**。
2. **客户端没数据**：服务端快照给单位只发技能 id 列表（`abl`），从未发 `art.icon`；客户端也不知道 art 字段存在。作者原版的 hero 消息会带完整技能信息。

**修复方向**（接手的照做）：
- hud.js：`a.icon` → `a.art?.icon`，`\`→`/`、`.blp`→`.png`、加 `/assets/textures/` 前缀（参考 ui.js 的 cmdBtn/ICON_PATHS 做法）。
- 服务端：快照/单位消息把单位技能的 `art.icon` 一并发出（或客户端加载 abilities.json）。
- 然后核对：hud 按钮图是否真实、游戏内单位头像要不要 2D 图（WC3 的 portrait 源在 `units/xx/xx_portrait.mdx`——已转 996 glb，可渲染或烘焙）。

### 2. 技能端到端（训练链→技能按钮→放技能）未闭环

牧师/女巫可以训练出来了（hpri/hsor 数据已补），但**客户端没有单位技能按钮渲染链路**（选牧师看不到"治疗/驱散"按钮，也就没法放）。服务端 case 都在（abilities.js 57 case），缺的是两端接线：快照带技能 → 客户端按钮（带图标，参考遗留 1）→ 点击发 Msg.CAST。

### 3. 被动技能未接入攻击引擎

狮鹫链锤（Asth）、防空（Aflk 150 伤害/325 范围）、飞机炸弹（Agyb）——被动类，无需按钮，还没接到 damage/攻击结算。

### 4. 双人对战未实测

本地一直单人（slot 0）玩法验证。蓝方 slot 1 加入 → 对战/胜负/资源竞争链路未跑过。

### 5. WebGPU 渲染替换（用户铁律："只保留我们自己的渲染方法"）

foc-web 当前仍是 Three.js **WebGL** 渲染。曾做出独立 WebGPU 渲染栈（仓库 web/m2/，three r186 WebGPU 用法 + WASM 读图）——**还没合回主 client**。这是用户最在意的方向之一（"专注调优"）。

### 6. WASM/WebGPU 调优对比

"WASM 读图 + WebGPU 渲染"要出对比/调优数据（用户：专注调优）。

### 7. APK 打包架构难点（未解决，阻碍最终目标）

素材够，但引擎是 **Node 权威服务器**架构——APK 里跑不了 Node server。需：嵌入 Node runtime（如 NodeJS-mobile）或 APK 连局域网/云端 server。**纯静态离线 APK 不行**（玩家至少需要一个 server）。

### 8. 客户端 gameover 文本 1 处未改写

服务端发 "Team X wins" 模式，客户端有 1 处没转中文（其余已中文化）。
