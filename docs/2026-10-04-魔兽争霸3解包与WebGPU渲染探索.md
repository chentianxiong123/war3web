**关键 API**（mdx-m3-viewer）：
```js
const { parsers } = require('mdx-m3-viewer');
// 模型解析
const model = new parsers.mdlx.Model();
model.load(buffer);
model.name, model.bones, model.sequences, model.geosets, model.textures
// 贴图解码
const blp = new parsers.blp.Image();   // 注意: 是 .Image 不是 blp
blp.load(buffer);
blp.getMipmap(0)  // → {width, height, data: RGBA}
```

**WebGPU 要点**（three r186）：
- 渲染器是独立包：`import { WebGPURenderer } from 'three/webgpu'`
- **必须先 `await renderer.init()` 再渲染**，否则报 "backend is not initialized"

## ⑤ 踩坑记录（最有价值的部分）

**坑1：`smpq` 提取报 "No action specified"**
- 现象：`smpq -X file mpq` 报错
- 根因：参数顺序错，正确用法是 `smpq -x -o <mpq> <file>`（动作参数 `-x` 在 archive 前面，`-o` 是覆盖）
- 解法：`smpq -x -o War3Patch.mpq "路径"` ✓

**坑2：mdx-m3-viewer 在 Node 里报 `ImageData is not defined`**
- 现象：`blp.getMipmap()` 抛 ReferenceError
- 根因：库是浏览器向的，BLP 解码器内部用浏览器 API `new ImageData()`
- 解法：Node 里加 polyfill（5 行）：
```js
class ImageData {
  constructor(w, h) { this.width = w; this.height = h; this.data = new Uint8ClampedArray(w*h*4); }
}
global.ImageData = ImageData;
```

**坑3：`parsers.blp` 不是构造器**
- 现象：`new parsers.blp()` 报 TypeError
- 根因：解码器是 `parsers.blp.Image`，不是 `parsers.blp` 本身
- 解法：`new parsers.blp.Image()`

**坑4：three r186 WebGPU 报 "backend is not initialized"**
- 根因：WebGPURenderer 必须显式 `await renderer.init()`
- 解法：构造后先 init

**坑5：服务器端口 8080 被占**
- 现象：EADDRINUSE
- 解法：换端口 8090

## ⑦ 决策记录

- **选 smpq（StormLib）而非自定义解析**：命令一条出活，官方 C 库，稳
- **选 mdx-m3-viewer 而非自己写 BLP 解码**：BLP1 的 JPEG 变体格式复杂（16 字节 mipmap 表 + 自定义 JPEG 头），库自带 jpg.js 解码器，polyfill 一个 ImageData 就全通
- **选 three.js WebGPU 而非原生 WebGPU**：先验证链路，生态成熟；后续要做骨骼动画再加 TSL/shader
- （弯路：曾在 Windows 侧手动写 UEFI NVRAM 折腾过，与本次无关，交叉验证过 API 行为）
